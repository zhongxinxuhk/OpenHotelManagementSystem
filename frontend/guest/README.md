# 客户端（guest：H5 + Web）

> 身份平面：**GUEST**（住客）。与员工身份**不同表、不同会话、不同授权模型**。
> 状态：**待初始化**，且后端面未就绪。

## 为什么 H5 与 Web 放一个工程

客人的流程只有一条：**看房 → 选日期 → 下单 → 查/改订单**。
H5 与 Web 的差别是版式与输入方式，不是业务逻辑。拆成两个工程会让同一条下单流程被维护两遍，
而它们必须保持行为一致（价格、可用性、取消政策），这是最容易长期漂移的重复。

若将来 H5 要单独发布（例如走微信内、Web 走独立域名），把本目录复制成两个即可；
现在合在一起不会让那天变难。

## 技术栈

Vite + React + TypeScript + antd-mobile；
桌面断点复用同一套组件，用 CSS 断点与布局容器切换，不引第二套 UI 库。

## 初始化（须在宿主终端）

```bash
npm create vite@latest frontend/guest -- --template react-ts
cd frontend/guest
npm i antd-mobile react-router-dom
```

## 客户端的额外红线

1. **不信任 URL 参数判定支付成功**（J-09）。支付结果只能由服务端订单状态决定，
   从支付页返回的 query 参数可以被手工拼出来。
2. **不在前端存口令**。住客会话用独立令牌，不复用员工的不透明会话表。
3. **文案禁令更严**：面向消费者的页面最容易写进营销话术（"欢迎来到""立即开启"），
   本项目要求只写业务事实与字段标签（见 `docs/development/frontend-antd-pro.md` §7）。
