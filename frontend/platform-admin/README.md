# 平台管理员端（platform-admin）

> 身份平面：**PLATFORM**（跨租户，系统级）。
> 状态：**BLOCKED** — 依赖 DEC-01 / DEC-02；另有一项**需产品确认**的范围收敛（见下）。

## 定位

给平台技术/系统人员用的控制台。与 `platform-ops` 的分工：

| | platform-ops | platform-admin |
| --- | --- | --- |
| 服务对象 | 商家（外部客户） | 系统本身 |
| 典型问题 | "这家门店为什么收不到订单通知" | "租户建错了要停掉""备份是不是还在跑" |
| 数据粒度 | 某租户的业务数据 | 全平台的组织与运行状态 |

## 明确不做的两件事（**需产品确认**）

需求原文点名了"数据库管理、存储管理"。本端**不提供**这两项的网页入口：

1. **不做"能跑任意 SQL 的网页"**。应用账号 `pms_app` 故意没有 DDL 权限，
   迁移由独立 `pms_migrator` 账号执行（ADR-011/016）。一个能改库的网页等于把这条边界拆掉，
   而这个网页一旦被打穿，损失是**整库**，不是一家门店的数据。
   数据库级动作继续走"工单 + 人在机器上执行 + 事后记录"。
2. **不做对象存储的密钥管理界面**。密钥留在应用配置里，网页化只扩大泄漏面。

取而代之，本端是**受控运维控制台**：

- **只读诊断**：租户/门店清单、会话与登录审计、Outbox/Inbox 积压、对账差异、备份与恢复状态、
  公开面（`/api/v1/public/**`）流量与被刷情况；
- **受审计的少量写动作**：建/停租户、建门店、解锁账号、按租户导出；
- **组织架构管理**：租户与门店的增改（数据本身），不是数据库表结构管理。

> 这一定义改变的是"平台管理员端"的预期范围，**需要需求方确认**后写进范围文档。

## 为什么现在不能做

与 `platform-ops` 同因：不存在跨租户的合法身份（DEC-01/DEC-02）。
另外本端还额外需要：

- 平台动作清单与审批流（哪些动作必须双人复核？DEC-02、DEC-15）；
- 全量审计落库（B-05 目前只到一半）。

## 技术栈（定案后）

Ant Design Pro 6，独立部署。**必须独立域名或至少独立子域**：
它和商家端、业务端共用一套 cookie/令牌策略是不可接受的。
