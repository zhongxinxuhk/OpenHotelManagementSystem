# PMS 角色、权限边界与业务用例

> 版本：0.1；日期：2026-10-19；任务：S0-01。
>
> 配套：[首期范围](./scope.md)、[术语表](./glossary.md)、[业务决策台账](./decision-register.md)。角色为设计模板，用例为需求期望，不表示账号已授权或测试已通过。

## 1. 角色目录

| 编号 | 角色 | 主要职责 | 数据范围 | 默认不授予 |
| --- | --- | --- | --- | --- |
| ROLE-01 | 平台管理人员 | 租户开通、平台配置及运营支持 | 经授权的平台管理对象 | 所有租户住客明文、直接改账、直接修改房间占用 |
| ROLE-02 | 租户管理员 | 组织、员工、角色、门店数据范围 | 本租户内已获管理权限的对象 | 跨租户管理；将自身没有的权限转授他人 |
| ROLE-03 | 集团管理人员 | 跨店经营查看和获准的管理操作 | 明确授权的本租户门店集合 | 因品牌相同自动访问独立加盟租户 |
| ROLE-04 | 店长/定价人员 | 门店配置、价格、例外操作及业务复核 | 授权门店及批准的动作 | 任意资金修改、随意跳过入住或库存条件 |
| ROLE-05 | 前台人员 | 预订、排房、入住离店、续住换房及获准收款 | 当前获授权门店的业务对象 | 角色管理、跨店数据、超出授权额度的退费和敏感导出 |
| ROLE-06 | 房务人员 | 清洁、检查、维修申请及获准状态操作 | 授权门店的房间及所需最小入住提示 | 住客完整证件、资金、订单任意取消 |
| ROLE-07 | 财务人员 | 账项核对、收退复核、对账和日结 | 授权门店的财务数据 | 超出范围的集团数据、删除原始账项、绕过退款额度 |
| ROLE-08 | 渠道运营人员 | 渠道配置、映射、开售控制和差异处置 | 授权门店的渠道账户 | 导出密钥明文、绕过准入、伪造外部支付或确认结果 |
| ROLE-09 | 审计/经营分析人员 | 审计、经营报表和获准导出 | 明确授权的只读范围 | 常规业务修改；无审批的大量敏感信息导出 |
| ROLE-10 | 运维/安全人员 | 部署、监控、故障恢复、凭证和任务处置 | 经审批的环境、任务或临时支持范围 | 默认进入任意租户办理入住、改库存和资金 |
| ROLE-11 | 住客用户 | 自有渠道查询、预订、支付、取消及查看订单 | 通过服务端归属关系验证的本人对象 | 凭手机号/订单号相同获取其他人的订单 |
| ROLE-12 | 系统任务/外部适配器 | 超时扫描、消息、支付/OTA 回调、同步和对账 | 显式租户/门店/渠道/商户上下文与服务权限 | 无身份通用后台写入口、信任任意回调字段授予租户范围 |

同一员工可兼任多角色，但每个动作仍校验功能权限和目标数据范围。

### 1.1 平台侧角色的细分（多端需求提出后）

多端需求点名了"客服、售后、运营"与"技术、数据库、组织架构、存储"。这些**不新增 ROLE 编号**，
而是 ROLE-01（平台管理人员）与 ROLE-10（运维/安全人员）内部的职责细分。
理由：ROLE 表表达的是"数据范围与默认不授予什么"，而这类细分差异是**动作级**的，
应该用平台动作清单表达（A-07/A-08 实现时建立），不塞进租户内的 `role`/`permission` 字典。

| 细分职责 | 归入 | 典型动作 | 明确不做 |
| --- | --- | --- | --- |
| 客服 | ROLE-01 | 查租户与门店、看某订单为何失败、按工单回复商家 | 代商家改房价、改库存、退款执行 |
| 售后 | ROLE-01 | 投诉与退款**申请的流转** | 直接退款（资金动作属 DEC-08 授权范围） |
| 运营 | ROLE-01 | 开通进度、活跃度、话术与公告配置 | 读住客实名信息 |
| 平台技术 | ROLE-10 | 诊断、积压处置、备份状态 | 在 Web 上执行 DDL 或改库（ADR-017 §2.4） |
| 组织架构管理 | ROLE-01 | 建/停租户、建门店 | 改员工角色（属租户内权限） |
| 存储管理 | ROLE-10 | 看容量与备份状态 | 在 Web 上管理对象存储密钥 |

> 该细分的落地依赖 DEC-01/DEC-02：平台是否存在、跨主体能看多深，未定案前不实现（A-07/A-08 保持 BLOCKED）。

高风险操作是否要求第二人复核、额度阈值及紧急授权方式由 DEC-02/08/15 决定，不能在未确定前假定两名独立员工始终可用。

## 2. 授权与审计通则

1. 角色菜单只是体验层；服务端逐对象校验身份、角色动作、租户、门店及业务状态。
2. 列表、详情、批量操作、异步任务、导出创建和下载均执行相同的数据边界；不得只在入口页面过滤。
3. 身份停用或撤权按批准会话规则生效；缓存、后台任务和导出文件不能保留永久访问能力。
4. 关键写操作记录操作者或系统主体、归属、对象、命令、结果、原因及关联 ID；敏感字段按最小化规则记录。
5. 运维重放、补偿和业务复核调用受控命令；不能靠直改数据库绕开订单、占用或资金不变量。
6. 外部回调须建立可信来源和账号映射，再验证业务对象；请求中自报的 tenant_id、商户号和金额不能单独构成信任依据。

以下每个用例均继承这些规则。特定异常不得通过“无权限人工强改”作为兜底。

## 3. 组织与房间用例

### UC-01 开通租户与组织门店

- 角色：ROLE-01、ROLE-02；范围：F-01。
- 触发与前置：收到合法开通/组织维护需求，操作者已获得对应管理范围；租户与集团归属按 DEC-01 确认。
- 输入：主体标识、集团/门店名称与编码、所属关系、酒店时区和启停状态。
- 主流程：校验主体与编码 → 创建/维护组织关系 → 分配最小初始管理范围 → 记录审计。
- 成功结果：组织归属可追溯，门店仅在本租户授权范围内可见；初始化重试不重复建店。
- 异常路径：跨租户挂靠、重复编码或无权开通被拒绝；存在未履行业务的停用/删除申请进入受控处理，不级联删除交易历史。
- 待确认：DEC-01、DEC-02；后续任务：S1-02、S3-02。

### UC-02 员工授权、跨店切换与撤权

- 角色：ROLE-02、ROLE-03、ROLE-04；范围：F-01。
- 触发与前置：员工入职、换岗、离职或切换工作门店，授权人具备相应管理权限。
- 输入：账号、角色集合、门店范围、生效/失效条件和操作原因。
- 主流程：验证可授予范围 → 保存授权 → 更新会话/权限缓存 → 清理切店上下文 → 审计。
- 成功结果：功能权限与数据范围同时生效；撤权后的操作、下载及任务结果访问按规则受限。
- 异常路径：越级授权、混入其他租户门店、停用账号继续操作被拒绝；角色变更竞争按版本检查处理。
- 待确认：DEC-02、DEC-15；后续任务：S1-03、S3-02、S6-05。

### UC-03 维护房型与实体客房

- 角色：ROLE-04、获准的 ROLE-05；范围：F-02。
- 触发与前置：门店初始化或房间调整，操作者有门店及基础配置权限。
- 输入：房型编码、容量、房号、归属、启用状态及变更原因。
- 主流程：验证房型与门店归属 → 校验唯一性 → 保存配置 → 核对有效预订影响。
- 成功结果：房间归属唯一且可用于后续可售计算，所有变更留痕。
- 异常路径：同店重号、跨店房型、存在占用时破坏性变更被拒绝或进入明确迁移处置；不可直接删除已有履约记录的房间。
- 待确认：DEC-16 对资源粒度的影响；后续任务：S1-04。

### UC-04 设置维修、停用及解除

- 角色：ROLE-06、ROLE-04；范围：F-02。
- 触发与前置：维修计划或故障，操作者有相应申请/执行权限，时间区间有效。
- 输入：实体房、影响区间、原因、操作 ID、预期版本。
- 主流程：按统一资源锁序核对占用 → 决定允许生效或转人工协调 → 原子写入维修与库存影响 → 记录事件。
- 成功结果：生效维修区间不可售；合法解除仅恢复应恢复的可售范围。
- 异常路径：与预订同时竞争只能产生相容结果；已入住的紧急维修转明确的换房/处置流程，不能静默取消客人；重复解除不重复增加库存。
- 待确认：DEC-06 的入住例外流程；后续任务：S1-05、S3-06。

### UC-05 查询房态、连续可售与报价

- 角色：ROLE-05、ROLE-11、ROLE-12；范围：F-02、F-05、F-07。
- 触发与前置：准备预订或前台查看，查询者具备对应公开查询或员工权限。
- 输入：门店、住宿日期、房型、人数、房间数、价格计划和必要筛选。
- 主流程：校验日期及查询范围 → 计算完整住宿区间的可售资源 → 核价和入住限制 → 返回带版本/有效性信息的报价。
- 成功结果：员工得到授权房态视图，住客得到最小销售视图；可售与报价均明确不等于已锁房。
- 异常路径：缺价、无连续可用实体房、无效日期或过大窗口返回明确结果；派生数据滞后时下单仍由权威约束裁决。
- 待确认：DEC-05、DEC-09、DEC-16；后续任务：S1-12、S3-03、S3-07、S4-01。

## 4. 预订与前台用例

### UC-06 创建预订与临时锁房

- 角色：ROLE-05、ROLE-11、ROLE-12；范围：F-03、F-07。
- 触发与前置：提交有效预订意图；权限、门店、日期、人数及启用的价格政策已校验。
- 输入：幂等键、报价引用、房型/允许的实体房、日期、数量、最小联系人信息。
- 主流程：验证请求摘要 → 选择合法连续资源 → 同事务写订单、全部占用、流水、审计、Outbox 和结果 → 提交后响应。
- 成功结果：返回唯一预订与锁房结果，记录有效期；多房多晚全部写入。
- 异常路径：任一资源冲突整体回滚；同键异内容拒绝；响应丢失转 UC-25 查询，同键重试不重复创建。
- 待确认：DEC-03—DEC-06、DEC-09；后续任务：S1-07、S1-08。

### UC-07 确认预订

- 角色：ROLE-05、获准的 ROLE-04、ROLE-12；范围：F-03。
- 触发与前置：到店付、支付已核实或渠道规则允许确认，订单和占用满足批准状态条件。
- 输入：订单 ID、操作 ID、期望版本、确认依据及来源。
- 主流程：核验确认条件及占用 → 执行合法状态迁移 → 同事务记录流水/审计/事件 → 返回结果。
- 成功结果：确认订单具有真实有效占用及可追溯依据；资金状态保持独立。
- 异常路径：与取消/过期竞争按状态机判定；已失效占用不得直接复活；迟到支付转 UC-18/19 处理；重复确认返回既有结果。
- 待确认：DEC-06、DEC-08；后续任务：S1-09、S4-05、S5-03。

### UC-08 取消预订

- 角色：ROLE-05、ROLE-11、ROLE-12；范围：F-03、F-07。
- 触发与前置：合法取消请求，操作者有订单归属和取消权限，满足已批准政策。
- 输入：订单或允许的子项、操作 ID、期望版本、取消原因和政策引用。
- 主流程：判断可取消范围与收费 → 原子迁移订单/占用并一次性释放 → 发出退款或渠道通知任务 → 展示分别的处理进度。
- 成功结果：取消效果、释放效果及后续资金/渠道任务可关联；重复取消不产生额外效果。
- 异常路径：已入住、已离店、部分取消未启用或超政策取消被拒绝/转授权流程；退款未知结果不能写成已退；渠道未确认时遵循其协议。
- 待确认：DEC-04、DEC-06、DEC-08、DEC-11；后续任务：S1-09、S4-05/06、S5-04。

### UC-09 过期锁房释放

- 角色：ROLE-12，ROLE-10 负责异常处理；范围：F-03、F-11。
- 触发与前置：扫描发现到期且仍可过期的临时占用，领取任务后再次检查状态。
- 输入：批次、时间依据、租户/门店、到期记录和唯一释放操作标识。
- 主流程：竞争领取 → 再校验 → 同事务迁移占用、更新订单及释放流水/事件 → 提交。
- 成功结果：一次释放，任务失败可恢复；尚未完成事务迁移的到期记录仍按有效状态处理。
- 异常路径：并发确认获胜则跳过释放；Worker 崩溃可重领；支付未知或晚到进入协调流程而非盲目确认。
- 待确认：DEC-06、DEC-08；后续任务：S1-10、S2-03、S4-05。

### UC-10 排房与办理入住

- 角色：ROLE-05、获准的 ROLE-04；范围：F-04。
- 触发与前置：住客到店，预订与客房状态允许入住，必要信息及结算/押金要求已满足。
- 输入：订单、房间子项、最小入住人信息、操作 ID、版本和批准的例外依据。
- 主流程：核对身份与预订 → 验证房间/清洁/维修条件 → 必要时受控调整分配 → 创建入住记录并迁移相应状态。
- 成功结果：实际入住人与实体房关联，订单/占用/入住状态一致，敏感信息访问留痕。
- 异常路径：未清洁、维修、身份资料不足、未授权提前入住按批准规则阻止或转授权处理；重复办理不产生第二份有效入住。
- 待确认：DEC-04、DEC-06、DEC-12、DEC-13；后续任务：S3-04。

### UC-11 续住与同店换房

- 角色：ROLE-05、ROLE-04；范围：F-04。
- 触发与前置：已安排或已入住客人提出变更，具备变更权限，规则允许该操作。
- 输入：订单子项、延长日期或目标房间、报价差额、版本、操作 ID、原因。
- 主流程：按统一锁序校验目标区间 → 重报价 → 原子调整占用/入住关联和批准的账项 → 记录事件。
- 成功结果：目标占用合法，原有效占用按规则调整，差额和历史可追溯。
- 异常路径：目标被抢占或新增日期冲突时整体失败并保留原占用；重复提交不重复账项；跨店换房不自动按同店流程处理。
- 待确认：DEC-03、DEC-04、DEC-06、DEC-09；后续任务：S3-05、S3-07。

### UC-12 结算与离店

- 角色：ROLE-05、ROLE-07、获准的 ROLE-04；范围：F-04、F-06。
- 触发与前置：客人离店，已核对消费、实收、押金及批准的挂账条件。
- 输入：订单/房间子项、账务引用、操作 ID、版本、提前/延迟离店原因。
- 主流程：核对结算条件 → 合法终结入住及占用 → 记录差额/退款任务 → 将运营状态转待清洁。
- 成功结果：入住历史、账务和占用可追溯，客房不可因离店页面成功就跳过清洁规则重新办理入住。
- 异常路径：未结清且无挂账授权时阻止；退款处理中须明确显示而非伪造成功；重复离店不重复释放/入账；提前离店退款按政策处理。
- 待确认：DEC-04、DEC-06、DEC-08、DEC-09；后续任务：S3-04/08、S4-06。

### UC-13 认定 No-show

- 角色：ROLE-05、获准的 ROLE-04、获准的 ROLE-12；范围：F-04。
- 触发与前置：超过已批准入住截止条件且未入住；是否自动处理由政策决定。
- 输入：订单、当地业务时间、政策快照、操作 ID、版本及原因。
- 主流程：复核当前状态 → 认定 No-show → 按规则处理未来占用、费用和渠道通知。
- 成功结果：No-show 与取消、未付款过期区分，收费和释放均有独立依据。
- 异常路径：与入住同时发生时只允许合法一方迁移；政策未配置不自动扣费或释放；渠道预订按协议核实，重复扫描无重复效果。
- 待确认：DEC-06、DEC-07、DEC-11；后续任务：S1-09、S3-04、S3-09。

## 5. 价格、房务、资金与营业日用例

### UC-14 维护价格日历与价规

- 角色：ROLE-04、获准的 ROLE-03；范围：F-05。
- 触发与前置：发布或调整指定门店价格，操作者具备定价权限。
- 输入：房型、日期、价格计划、币种、税费口径、入住限制及取消政策版本。
- 主流程：校验金额与日期 → 保存版本 → 影响后续报价 → 生成必要渠道同步事件。
- 成功结果：新报价使用新规则，既有成交快照保留；改价行为有审计。
- 异常路径：缺价日期不可默认为零元；并发改价防止丢失更新；旧报价失效按规则要求重新确认，不能悄悄提高成交价。

- 异常路径：重复操作无重复账项；超额退押金、跨店账项、无凭据修正被拒绝/转复核；本地记账不能冒充第三方付款成功。

- 主流程：校验可退额度及在途退款 → 持久化申请 → 事务外执行 → 验签回调/查询 → 联动账务。
- 成功结果：每笔退款可追踪，累计退款受约束，业务取消与资金到账进度分开呈现。
- 异常路径：重复请求不重复退；未知结果不当作失败重新创建另一笔退款；超额/跨商户拒绝；永久失败产生可处置差异。

## 6. 渠道、可靠性与运维用例

### UC-21 接收 OTA 订单并确认

- 角色：ROLE-12、ROLE-08；范围：F-09。
- 触发与前置：已授权渠道推送或按协议拉取订单，账号与门店/房型/价格映射有效。
- 输入：实际作用域内外部订单号、请求标识、签名、住宿与金额字段。
- 主流程：校验来源与映射 → 去重及字段转换 → 调用统一预订服务 → 按协议响应接收或业务确认。
- 成功结果：一个外部订单映射到一笔合法本地订单，已确认结果具备有效占用。
- 异常路径：缺映射、无房、验签失败按协议拒绝/挂起；同订单不同请求不能重复建单；提交后响应丢失返回原结果；不能把接收回执冒充确认。
- 待确认：DEC-05、DEC-11；后续任务：S5-01—S5-03。

### UC-22 OTA 取消、修改与乱序核实

- 角色：ROLE-12、ROLE-08；范围：F-09。
- 触发与前置：渠道通知取消/修改/状态变化，来源可信且可定位账户和订单。
- 输入：外部订单、事件标识、协议版本/状态依据、修改内容及时间信息。
- 主流程：去重 → 判定事件新旧或查询权威状态 → 执行合法本地变更 → 回复/补偿任务。
- 成功结果：本地与渠道状态有可解释的对应，取消一次释放，修改满足原子资源约束。
- 异常路径：取消先于创建、旧确认晚到或无可靠版本时先核实/挂起；不能单靠接收时间覆盖新状态；变更失败不丢原有效预订。
- 待确认：DEC-04、DEC-11；后续任务：S5-04。

### UC-23 配置映射、推送库存价格与开售控制

- 角色：ROLE-08、ROLE-04、ROLE-12；范围：F-09。
- 触发与前置：授权账号启用、映射变更或库存/价格事件，操作者具有相关门店权限。
- 输入：渠道账户、门店/房型/价规映射、版本、同步范围、开售开关及原因。
- 主流程：核验映射 → 生成持久化推送任务 → 限流调用 → 记录结果/水位 → 对失败重试或校准。
- 成功结果：同步状态可见，旧任务不覆盖新值；暂停新售卖后仍能处理既有订单。
- 异常路径：无授权不启用；缺映射不推送猜测值；限流/超时有积压记录；推送成功不等于外部渠道绝不会继续超售。
- 待确认：DEC-05、DEC-11；后续任务：S5-02、S5-05、S5-08。

### UC-24 OTA 对账与可审计补偿

- 角色：ROLE-08、ROLE-12、需要时 ROLE-07；范围：F-09、F-11。
- 触发与前置：周期核对或收到渠道差异，具备授权数据和本地关联记录。
- 输入：渠道账户、时间窗口/水位、外部订单/库存/适用资金数据、批次 ID。
- 主流程：比对 → 识别漏单、错状态和同步差异 → 查询核实 → 受控补偿或业务处置 → 记录结果。
- 成功结果：差异能追踪至订单/事件/任务，重复批次不重复制造业务效果。
- 异常路径：渠道不可用则保留水位并重试；无法恢复的履约冲突交给明确责任人，不能强造占用；无对账接口时按实际协议制定替代核验方式。
