## 2. 产品目标与成功口径

目标是建立覆盖多租户、集团与门店运营的 PMS，支持实体客房预订、前台操作、基础账务、自有预订入口和授权 OTA 接入。500 家以上门店是架构容量目标，不是首批上线数量。

成功应表现为：

1. 合法预订只有在数据库完整提交后才返回锁房或确认成功，同一实体房间不能发生互斥日期内的重复有效占用。
2. 前台可完成预订、入住、续住/换房、结算、离店和清洁闭环，失败后保留可解释、可恢复的业务状态。
3. 重复请求、消息、回调、取消或退款不会重复改变库存和资金结果。
4. 集团和门店人员只能操作获授权的数据，住客只能访问属于自己的订单和个人信息。
5. 渠道、支付和基础设施异常可通过持久化记录、查询、重试、对账或人工处置恢复。
6. 可用性、数据恢复及性能目标在明确故障域、负载和观察窗口内得到验证，不能仅凭技术选型宣称达标。

## 4. 组织、经营模式与订单边界

### 4.1 组织与访问边界

- **租户**是签约经营主体和数据隔离边界；集团是可选组织层级；门店是实体客房、当地时区及日常运营归属。
- 建议一笔订单只属于一个租户和一家门店，多个房间属于同店；跨店组合行程以独立订单处理。这是 DEC-03 的建议，尚非已批准的跨店业务规则。
- 集团管理员只能查看显式授权范围内的门店。门店操作员不能通过替换对象 ID 访问其他门店。
- 住客身份、入住人、付款人和下单人可能不同，不能仅凭手机号相同就合并身份或授予订单访问权。
- 平台运维身份不自动取得所有租户的住客资料、账务修改和门店业务权限。临时支持访问需要明确范围、时效和审计。

### 4.2 直营与加盟

架构支持多租户与集团，但没有确定“一个品牌是否对应一个租户”或“加盟店是否共享经营数据”。本规划不按品牌名称推导租户归属。

| 场景 | 建议分析模型 | 尚待确认 |
| --- | --- | --- |
| 同一经营主体的直营门店 | 同租户下按集团/门店授权 | 集团可见数据和财务管理范围 |
| 独立签约、独立经营的加盟店 | 以独立租户作为候选隔离方式 | 合同关系、品牌授权、总部汇总需求 |
| 总部管理多个独立经营主体 | 显式定义跨主体汇总服务或授权模型 | 是否纳入首期、数据字段和撤权机制；不能直接扩大普通集团角色权限 |

DEC-01/DEC-02 定案前，可以继续设计租户隔离和门店权限，但不能将“所有加盟店可互查”作为默认实现。

## 6. 首期范围外与条件性扩展

| 项目 | 当前处理 | 纳入条件 |
| --- | --- | --- |
| 多 OTA 同时首发 | 延期；基础范围为一个渠道 | 每个渠道单独授权、估算、联调和验收 |
| 会员积分、营销活动、复杂团房/协议客户管理 | 延期，普通多房订单不等于团房协议产品 | 明确规则及对库存、价格和账务的影响 |
| 完整总账、税务核算、供应链及人事系统 | 不在基础 PMS 范围 | 与业务代表确认集成边界后独立规划 |
| 电子门锁、实名上报、电子发票等外部接口 | 尚未纳入已估算范围，不代表实际运营不需要 | DEC-13 确认是否为首期运营前提；若是则补充任务并阻塞相关上线 |
| 真正未分房的房型配额销售 | DEC-05 待定；建议首期内部即时实体分配 | 必须先设计配额、转占用、维修减量与跨日竞争规则并重新估算 |
| 跨店组合订单、跨租户统一收款及清算 | 暂不纳入建议基线 | DEC-01/03/08 扩展时增加领域、资金与权限设计 |
| 小时房、同日入住退房、房间内床位销售、自动拆段换房 | 尚未纳入日级实体房模型的建议首期范围 | DEC-16 若要求纳入，重新设计时间/资源模型和冲突约束 |
| 跨地域多主写入、服务网格、无证据的微服务拆分 | 原架构非目标 | 以明确业务/容量证据及 ADR 变更处理 |

## 7. 代表性业务验收故事

以下是需求级期望，用于产生后续测试，不是已经执行通过的测试结果。

| 故事 | 输入与操作 | 应看到的业务结果 | 对应规则/用例 |
| --- | --- | --- | --- |
| A-01 多人抢房 | 两名前台同时预订同店同房 `[2026-10-20, 2026-10-22)` | 最多一笔有效占用，另一方明确收到无房/冲突；相邻 10 月 22 日入住可独立预订 | BL-02/04、UC-06 |
| A-02 多房整体失败 | 一次预订两间房，其中一间有日期冲突 | 两间均不留下该请求的有效占用，也不出现半张成功订单 | BL-03、UC-06 |
| A-03 响应丢失 | 锁房提交后网络断开，原请求带同一幂等键重试 | 返回原交易结果，无第二笔订单 | BL-05/06、UC-06、UC-25 |
| A-04 维修竞争 | 房务提交维修时前台同时锁同房同日 | 只能形成一个合法结果；不能同时变成已确认预订和可生效维修 | UC-04、UC-06 |
| A-05 余量碎片 | A 房只在第一晚空闲，B 房只在第二晚空闲 | 未启用拆段换房规则时不能承诺一间房连续住两晚 | DEC-05/16、UC-05 |
| A-06 支付晚到 | 锁房已过期且房间被其他订单占用，再收到原支付成功 | 记录资金事实并进入已定义的退款/处置路径，不能抢回他人的占用 | BL-02、DEC-08、UC-18/19 |
| A-07 跨租户试探 | 员工或住客替换订单 ID、导出任务 ID | 拒绝无权访问且不泄露目标信息，后台任务同样受归属约束 | BL-07、UC-02/26 |
| A-08 OTA 乱序 | 相同订单重复通知，取消之后又收到旧确认 | 不重复建单，不重复释放，不复活已经合法取消的订单 | BL-06/09、UC-21/22 |
