# ADR-003：核心命令与交易记录原子提交

> 2026-10-19；S0-04；状态：同事务原则继承，写路径与恢复协议为待验证候选。

## 决定与范围

一次本地命令在单 PostgreSQL 短事务中完成：O/L/A 和必要 S/G、房晚净差、批准的本地账项或协调任务、O/房间版本、关键审计、Outbox、幂等成功结果。任何必要步骤失败均回滚。确认/入住没有资源增减时可以没有流水行，但必须有状态变更证据。

核心候选为 READ COMMITTED 加明确锁序、版本检查和数据库约束。授权在入口执行且关键状态锁后复核；多个 L 的主单汇总在 O 锁下完成。若需更高隔离，必须评估全事务重试，不能将隔离级别名称作为正确性证明。

## 外部协调

- Broker、支付、OTA HTTP、通知发送位于事务外。核心事务可靠写任务/Outbox，之后至少一次投递，消费者通过 Inbox 与业务效果同事务去重。
- Outbox 按 event_id 标识，允许同一聚合版本多个 ordinal；发布确认和数据库标记之间的故障允许重复。
- 可信资金事实先与可靠协调任务原子落库，再通过独立核心命令确认住宿。库存冲突不能回滚掉唯一资金恢复线索；具体财务状态留 S0-07。
- 暂不把跨服务 Saga 或分布式事务引入核心预订。未来拆服务必须重新说明哪些同事务不变量变成协议，不沿用“已经原子”的旧承诺。

## 净差、回退与验收

房晚流水按操作前后资源集合净差追加，唯一键含 operation、room、date、effect_kind；不能对 operation_id 单列唯一而阻止多房多晚。退房释放生效窗口由 S0-05 冻结，历史消费不冲销。

故障验证应覆盖第一/第二房写入、流水、审计、Outbox、commit 响应、发布标记和消费确认。已知失败整事务回滚；提交未知先查主库原结果。发布后的外部效果不能靠回滚本地 SQL 撤销，只能查询/补偿并保留历史。
