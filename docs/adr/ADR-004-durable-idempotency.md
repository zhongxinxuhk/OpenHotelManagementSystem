# ADR-004：持久化幂等、摘要与未知结果恢复

> 2026-10-19；S0-04；状态：持久化幂等原则继承，命令作用域与保留协议候选；渠道细则待 S0-06。

## 1. 作用域与请求意图

唯一键采用 `(tenant_id,hotel_id,caller_namespace,command_name,idempotency_key)`，所有列非空。caller_namespace 来自已认证调用方：员工/住客的稳定主体空间、受信渠道账户或后台任务空间；不同主体是否共享一个业务意图必须显式代理授权，不能由客户端任意指定 namespace。

key 表达一次意图，operation_id 是内部追踪标识；相同意图重试不换 key。规范化摘要包含命令、目标对象/子项、日期/房型/数量、expected_version、报价/政策版本及有业务意义的字段；排除 trace_id、认证 token、传输时间等。数组只在业务无序时排序，金额与日期按合同规范化；保存 hash_version，升级后仍可按旧规则核对原请求。同 key 异内容拒绝，不覆盖摘要。

## 2. 核心同步命令算法

1. 重新核验当前身份和对象范围；开始短事务。
2. 尝试插入本作用域记录（事务内可用 PROCESSING 状态），唯一键冲突等待有界。若冲突行存在，用后续 SELECT 读取；READ COMMITTED 下不能假定同一语句的冲突检测与快照必然看见相同行。
3. 已完成且摘要相同则回放原 result_code/ref/必要响应快照；历史结果与当前状态分开返回，不执行业务副作用。摘要不同返回冲突。
4. 新操作按核心锁协议执行，最后写 COMPLETED、结果、completed_at，与业务效果一起提交。PROCESSING 不单独提前提交；候选实现要求提交前断言已完成。
5. 约束冲突或业务拒绝时回滚本次全部数据，本版本不持久化所有确定性拒绝作为幂等成功结果。之后同 key 可重新评估尚未发生的意图；API 契约须明确失败结果不承诺永久缓存。

因此正常同步路径不会遗留可见的永久 PROCESSING 行。若发现这种异常，不用时间到期直接删行，先核实业务与故障来源。长任务使用独立任务表和租约，若接口结果只是“已接受任务”，其幂等成功结果也只能表示接受，不能表示住宿确认成功。

## 3. 结果未知、重放与权限

commit 响应丢失时向主库查询原作用域/key 和业务引用。没有收到成功、或副本暂时无记录，都不能推出未提交。主库不可用/故障切换期间返回待核实；必要的同键再执行仍经唯一约束等待和判定，不另造 operation 去抢第二间房。

旧 expected_version 仅属于原意图；同摘要原结果重放先于新的版本冲突判定。用户要修改日期、数量或期望版本时，应生成新意图/key并按新业务请求处理。撤权后不允许通过旧 key 读到原结果。响应不保存证件明文、访问 token 或支付秘密。

## 4. 外部业务键与消费者

渠道账户、门店映射、外部订单编号的作用域由真实协议决定；请求幂等 key 和“外部业务单唯一”是两道不同防线。外部订单有修改事件时不能把所有修改当重复创建，也不能因换了请求 key 就创建第二个本地 O。S0-06/S5 定义映射键及版本/查询核实策略。

Inbox 以已认证内部事件的 `(tenant,hotel,consumer,event_id)` 去重，与本地业务提交一致；同一 ID 异载荷摘要进入异常。不同事件 ID 即使同聚合版本也分别处理；领域命令还需保证不同操作不会重复产生同一资源/资金效果。

## 5. 保留与验收

未选只用 Redis TTL 或独立请求日志的方案，因为它们不能与本地住宿效果原子提交。独立 PROCESSING 加租约适合长任务，但需要额外恢复协议，本轮同步命令选择更简单的同事务完成方式；后续改为异步接受时，必须同步调整结果合同及任务恢复测试。

具体保留期限待 DEC-11/12，不任意填天数。详细响应可按隐私策略清理，但业务去重范围须保留最小墓碑或明确拒绝过旧请求；业务引用不可因清缓存而消失。对 key/摘要/actor 信息也按数据分类控制访问，不将它们等同于无敏感性数据。

验收包括同键并发、异摘要、跨作用域、撤权、提交响应丢失、主库切换、旧 key 超保留期及同版本多事件，见 [DM-21—DM-25](../domain/data-model-scenarios.md)。本稿未实现幂等表、算法或保留清理任务。
