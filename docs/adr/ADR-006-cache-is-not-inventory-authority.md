# ADR-006：Redis 与派生库存的非权威边界

> 2026-10-19；S0-04；状态：继承架构原则；与 [ADR-011](./ADR-011-technology-baseline.md) 的首期暂缓 Redis 决定一致。

## 决定

实体房间日期占用由 PostgreSQL room_occupancy、数据库约束和核心事务保证，实际在住由 S/G 与资源锁保证。Redis 如后续引入，只用于经评估的缓存、限流或短期协调，不作为最终库存账本，不以分布式锁替代数据库互斥，不承担持久化业务幂等的唯一副本。

## 读取与失效协议

- 房态投影/缓存携带来源房间版本和生成时间；缓存 TTL 是展示更新策略，不是库存释放条件。
- 成交前必须回到权威事务验证整个区间，不能因为缓存显示 1 间就绕过占用写入约束。
- 缓存丢失、清空或重启不会删除订单、释放锁房或复活终态；可按权威数据重建。
- 写入提交后通过可靠事件触发失效或重建；并发旧结果不能覆盖较新版本。发布失败期间允许缓存滞后，读路径必须识别或降级。
- 故障时缓存查询可降级到受控数据库查询；限流设施故障的放行/拒绝策略单独评审，不能把查询降级规则直接用到授权或支付限流。

## 代价、替代与验收

首期减少组件，热点压力由索引、查询窗口、数据库事务与测量解决。真正需要 Redis 时重新核验版本、许可、部署、内存上限、淘汰策略、连接预算和故障模式；不把“装上 Redis”当作容量或可用性验收。

执行缓存清空/失效事件丢失/乱序/重建竞争以及持续下单的数据库不变量检查；投影场景见 [DM-28](../domain/data-model-scenarios.md)，实际缓存故障测试在引入时补充。若未来变更权威边界，必须新 ADR 及可证明的事务/恢复方案，不通过配置开关静默切换。
