# ADR-002：统一占用排斥与房间资源锁

> 2026-10-19；S0-04；状态：数据库防重原则继承，统一表/锁顺序为待验证候选。

## 背景

两张表各自建立排斥约束无法阻止 A 与 B 的交叉重叠；日期合法相邻也不能证明前客已实际离店。数据库日期约束和运营事务检查各有职责。

## 决定

- A 的 HELD/CONFIRMED/CHECKED_IN 与 B 的 BLOCKED 在同一张 room_occupancy 表、同一条 GiST 排斥约束中互斥，资源键含 tenant/hotel/room，范围用 daterange。
- 区间非空、有界且边界日期有限；API 明确入住包含/退房不包含。kind/status/引用组合和 NOT NULL 独立校验，过期时间不进入约束谓词。
- 每条写路径按“幂等→O/L→全部房间升序→A/S/G 等关联”持锁到提交；无 O 的维修不反向获取订单锁，冲突进入另一次协调命令。
- 实际入住用活动 G 的 room/session 双唯一及同房资源锁；清洁、超住、禁售等仍需服务检查，排斥约束不代替这些条件。
- 先退役操作内全部旧 A 再插入全部新 A，失败全回滚；不依赖先释放的独立事务，不默认设置延迟排斥约束。

PostgreSQL 提供范围重叠与排斥约束；锁协议仍可能遇到死锁，需要按完整事务恢复。[范围文档](https://www.postgresql.org/docs/17/rangetypes.html)、[锁文档](https://www.postgresql.org/docs/17/explicit-locking.html)。

## 代价与限制

统一房间锁会串行化同房操作，是当前单体正确性优先的选择；是否缩短锁持有时间应由压测决定。BLOCK 与 BLOCK 重叠也被拒绝，多工单要引用同一封房事实。禁用约束、绕过锁或将有效事实拆到无法全局互斥的分区均不属于优化手段。

## 验收与回退

S1-05 验证扩展权限、双方向预订/维修竞争、相邻区间、非法范围、过期未清理和批量互换；S3 验证实际在住冲突。若统一表被后续决定替代，必须重新证明所有写路径的跨表互斥并迁移现存事实，不允许仅恢复原概念 DDL 就宣称等价。
